## Hilo (Thread) — Explicación completa

**Tweet 1 — Apertura**
```
Estuvimos pensando mucho en cómo los equipos gestionan fondos cripto compartidos.

La mayoría de los setups tiene un problema fundamental: demasiada confianza en muy pocas personas.

Así lo resuelve Trezu. 🧵
```

**Tweet 2**
```
La idea central: una tesorería es una wallet compartida donde ningún miembro tiene control unilateral.

Toda acción — pagos, swaps, cambios de configuración — requiere aprobación colectiva.

Eso no es nuevo. Pero el detalle está en el diseño de los roles.
```

**Tweet 3**
```
Trezu tiene 3 roles, separados intencionalmente:

🔵 Requestor → crea propuestas, no puede aprobarlas
🟢 Finance → aprueba/rechaza, no puede crear propuestas
🔴 Governance → controla configuración (miembros, umbrales), no puede mover fondos

Se pueden combinar. Pero lo hacés conscientemente.
```

**Tweet 4**
```
La separación de Governance es lo que la mayoría de las plataformas pasa por alto.

En Trezu, quienes configuran la tesorería (reglas de votación, membresía) están explícitamente bloqueados de mover fondos.

Governance es poderoso. Por eso está separado de las operaciones del día a día.
```

**Tweet 5**
```
El flujo de un pago:

1. Requestor envía una propuesta con monto y destinatario
2. Miembros de Finance votan (asíncrono, ventana configurable)
3. Se alcanza el umbral → se ejecuta automáticamente on-chain
4. Rechazado → los fondos nunca se mueven, motivo registrado

Simple. Auditable. No-custodial.
```
