## Thread — Full explanation

**Tweet 1 — Opening**
```
We've been thinking a lot about how teams manage shared crypto funds.

Most setups have a fundamental problem: too much trust in too few people.

Here's how Trezu approaches it. 🧵
```

**Tweet 2**
```
The core idea: a treasury is a shared wallet where no single member has unilateral control.

Every action — payments, swaps, configuration changes — requires collective approval.

That's not new. But the devil is in the role design.
```

**Tweet 3**
```
Trezu has 3 roles, intentionally separated:

🔵 Requestor → creates proposals, can't approve them
🟢 Finance → approves/rejects, can't create proposals
🔴 Governance → controls configuration (members, thresholds), can't move funds

Roles can be combined. But you do it consciously.
```

**Tweet 4**
```
The Governance separation is what most platforms miss.

In Trezu, the people who configure the treasury (voting rules, membership) are explicitly blocked from moving funds.

Governance is powerful. That's why it's kept away from day-to-day ops.
```

**Tweet 5**
```
The payment flow:

1. Requestor submits a proposal with amount and recipient
2. Finance members vote (async, configurable window)
3. Threshold reached → executes automatically on-chain
4. Rejected → funds never move, reason recorded

Simple. Auditable. Non-custodial.
```

**Tweet 6**
```
Cross-chain from day one.

30+ blockchains: Ethereum, NEAR, Solana, Bitcoin, Polygon, Sui, TON, Cardano and more.

One interface. No juggling wallets per chain.
Built-in cross-chain swaps directly from the treasury.
```
