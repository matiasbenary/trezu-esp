## Hilo — Para equipos financieros y de operaciones

**Tweet 1 — Apertura**
```
Si tu empresa opera con activos digitales, en algún momento vas a necesitar que tu tesorería cripto tenga los mismos controles que el resto de tus finanzas.

Acá explicamos cómo estructurarlo con Trezu. 🧵
```

**Tweet 2**
```
El primer problema que aparece en auditorías:

Las mismas personas que solicitan pagos también pueden aprobarlos.

No hay segregación de funciones. No hay control sobre quién autorizó qué.

Eso no sería aceptable en pagos bancarios. En cripto, es la norma.
```

**Tweet 3**
```
Trezu define tres roles con responsabilidades estrictamente separadas:

Requestor → inicia la operación, no puede autorizarla
Finance → autoriza, no puede iniciar ni configurar el sistema
Governance → administra accesos y reglas, no puede ejecutar operaciones

Mínimo privilegio aplicado a tesorería digital.
```

**Tweet 4**
```
Los umbrales de aprobación se configuran según el nivel de riesgo:

Operaciones estándar → 2 de 3 Finance
Operaciones de alto valor → 3 de 3 Finance
Cambios de configuración → requieren rol Governance con firma desde hardware wallet

La política financiera de la organización se traduce directamente al sistema.
```

**Tweet 5**
```
Cada transacción queda registrada con:

→ Quién la solicitó y con qué justificación
→ Quién votó y en qué momento
→ Cuándo se ejecutó y en qué red

Trazabilidad completa. Exportable. Inmutable on-chain.
```

**Tweet 6**
```
La gestión de accesos también tiene proceso formal.

Incorporar un nuevo firmante o revocar el acceso de uno existente requiere:
→ Propuesta formal desde un rol Governance
→ Aprobación de otro miembro Governance
→ Registro on-chain del cambio

Sin claves compartidas. Sin accesos residuales después de una desvinculación.
```
